## 2. 进程与窗口模型

```
src-tauri/src/lib.rs::run()
├─ 插件：opener / dialog / process / updater / pinia(tauri-store)
├─ setup：托盘(tray.rs) + 主窗口 CloseRequested→close_to_tray 则 hide
```

## 3. 单一 FFmpeg 执行路径（R2.1 起，核心事实）

### 3.1 新路径（演进方向）

```
前端 taskStore.addTask(commandLine)
  → invoke('task_manager::start_ffmpeg', { command, taskId })
      → shell_words::split 解析
      → Command::new(program).args(...).stdout/stderr piped spawn
      → TASK_PROCESSES: Mutex<HashMap<String, u32>> 登记
      → 后台线程读 stderr：
           PROGRESS_RE（frame/fps/time/bitrate/speed/size）→ emit "ffmpeg-progress"{taskId, ProgressInfo}
           全量 stderr 行 → emit "ffmpeg-log"{taskId, level, message}（R1-6 起全量转发，level=error/info）
           进程退出 → emit "ffmpeg-finish"/"ffmpeg-error"{taskId, code}
暂停/恢复：Unix SIGSTOP/SIGCONT；Windows NtSuspendProcess/NtResumeProcess（均已实现）
停止：SIGTERM（Unix）/ kill（Windows）
stdin：send_ffmpeg_stdin
CPU affinity：Unix sched_setaffinity（settings 有 taskPriority 字段但未接入）
```

事件消费方（R2.1 起统一为两类；事件名与 payload 类型单一事实源是 `src/utils/ffmpegEvents.ts`）：

| 消费方                                   | 适用                   | 调度方式                                                  |
| ---------------------------------------- | ---------------------- | --------------------------------------------------------- |
| `taskStore.setupEventListeners()`        | 编码队列任务           | store 统一并发闸门、终态保护、日志归集                    |
| `useTransientFFmpegTask`（`src/hooks/`） | 一次性任务（画质评测） | 不进队列、不占并发额度；`createListenerRegistry` 统一释放 |

两者都只监听 `ffmpeg-*` 前缀事件并按 `taskId` 过滤，停止都走 `stop_process(pid)`。

**R1 修复后的任务状态契约（2026-11-07）**：

- `runningCount` 不再是手工维护的 ref，而是从 `tasks` 派生的 `computed`（Processing + Paused 计数），重复扣减/竞态窗口从根上消除。
- `startTask` 自带并发闸门（任何调用方都无法绕过），`tryStartNext()` 一次填满可用额度；Paused 任务再次 start 转 `resume_process`，Processing 任务直接 return。
- 状态类事件（progress / finish / error）对终态（Completed / Error / Stopped）任务一律忽略；`stopTask` 先打 `stoppedByUser` 标记再 invoke，覆盖子进程退出后迟到的 `ffmpeg-error`。日志事件仍照收（不改写状态），便于排障。
- `ffmpeg-log` 由后端转发全量 stderr 行，前端 `selectTaskLogs(logs, outputType)` 决定展示全量还是仅错误行。

### 3.2 legacy 路径（R2.1 已删除）

删除前的形态：`useFFmpegCommand` hook / QualityAssess 直接 `invoke('execute_ffmpeg_command')`
→ `utility/_executor.rs` 自定义双引号 parser → `GLOBAL_PID` 单进程
→ 全局广播无前缀事件 `progress` / `finish` / `error`（无 taskId，多监听者互相串扰）。

**R2.1 删除清单**：`commands/legacy_executor.rs`；`utility/` 整个目录
（`_executor.rs` / `_constant.rs` / `mod.rs`）；`lib.rs` 的 `mod utility;` 与
`execute_ffmpeg_command` / `stop_convert` 注册；`hooks/useFFmpegCommand.ts`
（**零调用方死代码**）及 `hooks/index.ts` 导出。

**保留**：`library/_process.rs::kill_process`、`library/_tauri.rs::emit_payload` 是通用基础库，
删 legacy 后暂无调用方，留待后续清理（`pub fn`，不产生编译错误）。

**防复发门禁**：`src/__tests__/unit/config/legacyPath.test.ts` 静态断言前端/Rust 源码
不再出现两个 legacy command、无前缀事件或 `FFmpegEvent` 枚举，并校验 `FFMPEG_EVENTS`
常量与 Rust `task_manager.rs` 的 emit 字符串一一对应。

### 3.3 调用方分布（R2.1 后：一条执行路径，两类调度）

| 页面                      | 调度类型                                   | 备注                                                                                         |
| ------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------- |
| EncodingQueue（主流程）   | 队列任务（`taskStore.addTask`）            | 并发闸门 + 终态保护                                                                          |
| Mux / IndependentPanel    | 队列任务（`taskStore.addTask`）            | —                                                                                            |
| QualityAssess（画质评测） | **一次性任务**（`useTransientFFmpegTask`） | 同样走 `start_ffmpeg`，不进编码队列、不占并发额度；VMAF/SSIM/PSNR 从 `ffmpeg-log` 全量行解析 |
| Merge                     | 队列任务                                   | 原文档标注「需复核」：`useFFmpegCommand` 实为零调用方，Merge 未走 legacy                     |
| ffplay 播放控制           | 独立 command                               | `start_ffplay` 等 5 个，FFPLAY_PROCESS 单进程                                                |

**共同点**：唯一进程管理实现是 Rust `task_manager`，事件一律 `ffmpeg-*` 前缀 + `taskId`，
停止都走 `stop_process(pid)`。差异只在调度层：队列任务由 `taskStore` 统一并发调度，
一次性任务由 hook 自行管理生命周期（`start` / `stop` / `dispose`）。

**R2.3 设置链路**：Vue 上下文外的读取方（`i18n/index.ts`、`utils/ffmpegPath.ts`、`store/taskStore.ts`）直接调 `config/settings.ts::loadSettings()`；Vue 内一律用 `store/settingsStore.ts`（`commit()` 负责规范化 + 持久化 + `setLocale` + `applyTheme`）。`App.vue` 监听唯一键的 `storage` 事件后调 `reload()` 跨窗口同步。旧键 `theme` / `language` / `appSettings` 只在首次迁移时读取一次并立即写入新键，不再双写；`ffmpeg_settings` 无 UI、无消费方，原样保留不迁移。

**R2.4 预设链路**：`types/preset.ts`（`PresetData` + `DEFAULT_PRESET` + `PRESET_SCHEMA_VERSION = 1`）→ `config/presetSchema.ts::normalizePreset`（按默认值模板逐字段校验类型、丢弃未知字段、软升级旧版本 / 软降级未来版本、迁移 `advanced_params` 别名、ISO 字符串化时间）→ `store/presetStore.ts`（读写都过规范化）→ Rust `preset_manager.rs`（`serde_json::Value` 原样读写 `presets/<id>.json`，只补充 id / createdAt / updatedAt）。`createDefaultPreset()` 提供独立深拷贝，`{ ...DEFAULT_PRESET }` 浅拷贝已被静态门禁禁止。`createdAt/updatedAt` 统一为 `string`，与 Rust rfc3339 及 Tauri JSON 边界一致。

**R2.5 队列链路**：`config/taskQueueSchema.ts::serializeTaskQueue`（只挑元数据、时间转 ISO、上限 500 条）→ `taskStore` 的 `persistedSnapshot` computed → `watch` 触发 `flushPersist()`（串行化 + 合并写，最后一次快照保证落盘）→ Rust `task_queue_store::save_task_queue`（512 KiB 上限 + JSON 对象校验 + `tasks.json.tmp` → `rename` 原子替换）。启动时 `main.ts` 仅在 `getCurrentWindow().label === 'main'` 调 `restoreQueue()`：读 `load_task_queue` → `restoreTasks()` 清洗并迁移状态 → 抑制写盘完成 hydration 后写回一次。日志/进度因不在快照里，**高频变化不触发任何磁盘写**。`@tauri-store/pinia` 插件虽注册但 `autoStart=false`、无 store 启用，不参与该链路（整 store 持久化会把 `Date`/日志/pid 一并写入，且无迁移语义）。

**R1-7 设置生效链路**：`presetStore.presetDirArg()` 读 `AppSettings.presetDir`（空串 → null）→ Rust `resolve_preset_dir`（纯路径计算，自定义优先、空值回退默认）随 `load/save/delete_preset` 的 `dir` 参数生效。输出目录：`settingsStore.taskOutputDir`（唯一 computed，仅 custom 模式生效）→ 6 个生产调用方与 CLI 注入 `createTaskDraft(s)` 第 4 参 → `taskDraft.resolveOutputFile` 覆盖 `preset.output.location`；显式指定 outputFile 时不受设置影响。防线：`settingsEffectSingleSource.test.ts`。

**R3.1 分享链路**：`config/presetShare.ts::serializePresetShare`（`format`/`version`/`exportedAt`/`preset` 信封，剥离 id 与时间）→ `presetStore.exportPreset` → Rust `export_preset(file_path, content)` 纯文本写盘；导入反向：`import_preset(file_path) -> String` → `parsePresetShare` 校验格式/版本并兼容 legacy 裸 JSON → `normalizePreset` → `savePreset` 生成新 id。文本分享码走 `encodePresetShareText` / `parsePresetShareInput`（UTF-8 + base64url，64 KiB 上限），与文件通道共用同一解析层。`presetShareSingleSource.test.ts` 守住 Rust 零格式知识、store/UI 不自行 JSON 解析。

**R3.2 历史链路**：`taskStore.tasks`（R2.5 快照恢复结果）→ `config/taskHistory.ts::buildTaskHistory` 投影终态 → `summarizeHistory` / `filterHistory` / `sortHistory` 喂给 `pages/History/index.vue`；体积由页面批量调 Rust `get_file_sizes(paths) -> Vec<Option<u64>>` 后传入 `rankByCompression`（只算成功任务，文件不存在显示「体积不可用」）；导出经 `exportHistory` 生成 CSV/JSON 文本并复制到剪贴板；清空经 `taskStore.clearHistory()`。Rust 无历史结构体、无 `history.json`、无第二套统计口径，防线为 `taskHistorySingleSource.test.ts`。

## 8. 安全与外部边界

- **CSP**（tauri.conf.json）：`default-src 'self'`；connect-src 白名单 `self ipc: http://ipc.localhost https://api.github.com https://gitee.com`；style 允许 unsafe-inline（Vue 运行需要）；构建期有 `assert-csp-safe-build.mjs` 断言无 eval/new Function。
- **updater**：指向 GitHub releases（国内可达性问题，见审计 §3.3）。
- **命令注入面**：R2.1 起只剩 `task_manager` 一条路径，用 `shell_words::split` 解析（替代 legacy 的双引号 parser + 危险字符黑名单）。命令字符串仍由前端构建——**前端命令字符串是信任边界输入**；`useTransientFFmpegTask` 的评测命令同样来自页面拼接，改动时需保持引号与参数校验。
- identifier：`com.william.ffmpeg-desktop`（注意连字符，旧文档写的是下划线版本，是错的）。
