# FFmpeg Desktop 重构路线图

> 更新：2026-11-07 | 依据：《项目现状审计报告》全部证据 | 原则：先固化正确性 → 再收敛架构 → 后扩展功能
> 本文是建议方案，非实施承诺。每个条目标注了对应的审计问题编号（如 P0-1）以便溯源。

---

## 0. 总体策略

**当前项目处于"功能完备但可信度未立"状态。直接叠加新功能会放大既有分裂。建议按四个阶段推进，前两个阶段不做任何新功能：**

```
阶段 R0 治理基线（1 周量级）—— 版本、文档、验证清单，让"项目是什么状态"有唯一答案
阶段 R1 修复断裂（2-4 周量级）—— P0/P1 缺陷清零，让既有功能真正可用
阶段 R2 架构收敛（1-2 月量级）—— 双路径合一、状态体系统一，让代码可维护
阶段 R3 产品进化（开放）—— 体验重设计 + 功能扩展，让产品有差异化
```
