# FFmpeg Desktop UI/UX 重设计规范

> 更新：2026-11-07 | 适用：阶段 R3（须在 R1 交互链路修复完成后启动）
> 性质：设计规范文档，指导后续实现；本文不包含代码交付

---

## 1. 设计定调（Direction Lock）

- **目的**：给内容创作者和视频处理者一个**可信、高效、信息密集但从容**的批量转码工作台。
- **用户画像**：三类——① 批量压制视频的创作者（主）；② 需要精确控制编码参数的进阶用户；③ 偶尔转一个文件的轻度用户（须被 ①② 的复杂度保护起来，而非驱逐）。
- **调性选择**：**工业实用（Industrial / utilitarian）**——仪表盘密度、等宽数字、发丝边框、克制的状态色体系。工具类应用的正确方向；拒绝"极简到空"也拒绝"装饰堆砌"。
- **记忆点（唯一一个）**：**实时编码监视墙**——队列页每个任务卡上的等宽数字进度（fps / speed / ETA / 已写大小）像机房仪表一样跳动。这是同类竞品都做得敷衍的地方，做到极致就是辨识度。
- **禁入方向**：营销页式大标题、玻璃拟态全家桶、紫色渐变、装饰性图标墙。

## 2. 信息架构重构（本规范最重要的一节）

### 2.1 核心判断

当前 12 个平级页面是**"复刻原版页面"的产物，不是用户任务流的产物**。用户的心智模型是一条管道：

```
拿到文件 → 决定参数 → 排队跑 → 看结果
```

而当前 UI 把这条管道切成三个平级菜单项，默认落地页还是空队列。

### 2.2 导航重组方案

```
┌─ 工作台（默认落地）─────────────────────┐
│  管道式单页流：                         │
│  ① 文件区（拖入/选择，含文件夹扫描）     │
│  ② 参数区（预设 + 手动参数，折叠式）     │
│  ③ 队列区（常驻右栏或底部，可展开监视墙）│
└───────────────────────────────────────┘
工具（次级导航，收纳低频功能）：
  合并 / 混流 / 画质评测 / 媒体信息
监视（次级导航）：
  队列详情 / 性能监控
系统：
  设置
```

- **默认落地页 = 工作台**（替代当前空 `/queue`），空态即引导："拖入视频文件开始"。
- Home 页取消独立页面地位，其"快速入口"并入工作台空态。
- Player、Performance、MediaInfo 降级为工具/监视入口，不再平级占位。
- 独立面板窗口保留（多参数对照是真实需求），入口收进文件区右键/批量菜单。

### 2.3 任务流断点修复清单（UI 侧）

| 断点                             | 期望行为                                       |
| -------------------------------- | ---------------------------------------------- |
| 添加到队列后清空全部文件（P1-7） | 文件保留未选项，带"已入队"徽标                 |
| 无文件夹扫描（P1-6）             | 拖入文件夹 = 递归扫描出媒体文件列表            |
| 预览按钮 console.log（P2-6）     | 调用媒体信息浮层（ffprobe 结果 + 首帧缩略图）  |
| 选中链路断裂（P0-2）             | 任务卡可选中 → 详情面板（日志/stdin/精确控制） |

## 3. 设计 Token 体系（重建 `theme.css`）

### 3.1 现状与差距

现有 token：`--bg-color1..5`、`--text-color1..2`、`--active-color`、`--info-color` 等——编号式命名、无语义、无字阶/间距/圆角/阴影/动效 token，组件大量 scoped 手写数值。

### 3.2 目标 token 骨架（语义别名 + 旧名兼容映射期）

```css
:root {
  /* 颜色（语义别名，组件只允许用这些） */
  --color-bg: #111318; /* 主表面 */
  --color-surface: #191c23; /* 卡片/面板 */
  --color-surface-raised: #21252e; /* 浮层 */
  --color-border: rgba(220, 228, 240, 0.1); /* 发丝边框 */
  --color-text: #e8ecf2;
  --color-muted: #8b93a1;
  --color-accent: #4da3ff; /* 唯一强调色：仅关键动作与选中态 */
  --color-ok: #3fb96a;
  --color-warn: #e0a63b;
  --color-err: #e05663;
  /* 状态色纪律：任务状态色只用于状态条与徽标，不做大面积填充 */

  /* 字阶（1.25 模数，禁止手写数值） */
  --fs-2xs: 11px;
  --fs-xs: 12px;
  --fs-s: 13px;
  --fs-m: 16px;
  --fs-l: 20px;
  --fs-xl: 25px;
  --fs-2xl: 31px;
  --lh-body: 1.6;
  --lh-tight: 1.1;

  /* 间距梯度 */
  --sp-1: 4px;
  --sp-2: 8px;
  --sp-3: 12px;
  --sp-4: 16px;
  --sp-5: 24px;
  --sp-6: 32px;
  --sp-7: 48px;
  --sp-8: 64px;

  /* 圆角 / 阴影（三级，阴影带环境色） */
  --r-sm: 4px;
  --r-md: 8px;
  --r-lg: 14px;
  --sh-1: 0 2px 8px rgba(8, 10, 14, 0.3);
  --sh-2: 0 8px 28px rgba(8, 10, 14, 0.38);
  --sh-3: 0 24px 64px rgba(8, 10, 14, 0.48);

  /* 动效 */
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
  --dur-fast: 160ms;
  --dur-base: 320ms;
  --dur-slow: 640ms;
}
[data-theme='light'] {
  /* 同名覆盖，组件代码零改动 */
}
```

- **数据数字一律等宽**：进度、fps、码率、大小用 `font-variant-numeric: tabular-nums` + mono 字体（JetBrains Mono / IBM Plex Mono）。
- 明暗主题经 `[data-theme]` 覆盖语义 token；旧 `--bg-color1` 等保留一个 minor 版本作兼容映射（`--bg-color1: var(--color-bg)`），R3 结束后删除。
- 当前 light 主题同样是第一公民（IDE/系统为浅色时的用户占比不低），两套都要过对比度检查。

### 3.3 字体策略

- **正文/UI**：系统栈打底（现有 PingFang/Segoe 栈可保留——桌面工具正文用系统字是正确选择，且无网络字体依赖，符合 CSP `font-src 'self'`）。
- **数据/命令**：内嵌一款 mono 字体自托管（JetBrains Mono 子集化打包进 assets），用于命令预览、日志、进度数字。
- **禁止**：引入网络字体（CSP 与离线场景都不允许）；把 Inter/Roboto 类字体当"设计升级"。

## 4. 关键界面规格

### 4.1 任务卡（记忆点载体）

```
┌────────────────────────────────────────────┐
│ ▎ ● Processing   input.mp4 → output.mp4    │  ← 左侧 3px 状态色条（不只靠颜色，附图标+文字）
│   [###########·······]  47%                │
│   fps 118  ·  speed 3.4x  ·  ETA 2m 18s    │  ← 等宽数字监视行
│   812 MB / est 1.7 GB      libx265 crf 20  │
└────────────────────────────────────────────┘
```

- 状态表达：色条 + 图标 + 文字三重编码（可访问性要求，禁仅用颜色）。
- 选中态：`--color-accent` 描边 + 详情面板联动。
- 失败态：展开行内错误摘要 + "查看日志"直达，错误信息可复制。

### 4.2 队列页整体

- 三区布局：左（文件/参数折叠区）中（任务列表）右（选中任务详情：日志/stdin/命令预览）。
- "开始全部"按钮文案改为"启动队列"，旁边常显并发数徽标（`2/4 运行中`），把 `maxConcurrent` 从隐藏设置变成队列页直接可调。
- 日志过滤（全部/仅错误）真正生效（对应 P1-3 修复后的 UI 落点）。

### 4.3 空态设计（当前完全缺失）

每个列表型界面必须设计空态：一句话 + 一个主动作。例：队列空态 = "队列是空的，从工作台添加任务" + 按钮"去添加文件"。

### 4.4 表单与危险操作

- 参数面板 13 个 tab 的 `v-show` 全挂载保留（切换响应优先），但 tab 加"已修改"圆点指示。
- 危险操作（删除任务、清空队列、覆盖输出文件）一律走 `ConfirmDialog`，文案写明后果（现有规范已有，执行层面补齐遗漏页面）。

## 5. 动效规范

| 场景            | 规格                                                                                 |
| --------------- | ------------------------------------------------------------------------------------ |
| 页面/工作台入场 | 一次编排：3-6 组错峰（60-120ms 间隔），只动 opacity + translateY，`--dur-base`       |
| 任务卡新增      | 从上方 8px 滑入 + 高亮 400ms 渐隐                                                    |
| 状态切换        | 仅色条与徽标 `--dur-fast` 过渡，卡片本体不动                                         |
| 进度数字        | **不做逐帧动效**（性能 + 可读性），节流到 500ms 刷新                                 |
| 降级            | 全部动效包进 `@media (prefers-reduced-motion: no-preference)`；reduce 时立即呈现终态 |

## 6. 可访问性规范（当前几乎为零，逐项补课）

| 项             | 要求                                                                                  | 现状差距                                          |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 焦点可见       | 全局 `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px }` | 大量 `outline: none`                              |
| 导航键盘可达   | 导航项用 `button`/`router-link` + `aria-current="page"`                               | 现为 `div`，不可聚焦                              |
| 触摸/点击目标  | ≥ 44×44px                                                                             | 按钮最小高度约 32px                               |
| 颜色非唯一编码 | 状态 = 色 + 图标 + 文字                                                               | 任务状态仅色条+文字                               |
| 对比度         | 正文 ≥4.5:1，大字 ≥3:1                                                                | 需逐 token 实测（明暗两套）                       |
| 动效降级       | `prefers-reduced-motion`                                                              | 完全没有                                          |
| i18n 完整      | 所有用户可见文案走 `t()`                                                              | TaskProgress"秒"、Mux、QualityAssess 有硬编码中文 |

## 7. 反 AI 味 / 品质自检表（每次 UI 迭代 PR 过一遍）

1. 本页有没有一个说得出理由的视觉决策（而不是"看起来还行"）？
2. 数字是否等宽对齐？同一列数据是否右对齐？
3. 间距是否全部来自 token（搜索手写 px 值数量趋零）？
4. 状态色是否只在状态处出现？
5. 空态/加载态/错误态是否齐全？
6. 键盘能否走完本页主流程？
7. 明暗两套主题是否都实测过对比度？
8. 新增文案是否中英双语同步？
9. 有没有引入网络请求型资源（违反 CSP/离线）？
10. 换个 Logo 还认得出这是本产品吗（监视墙等记忆点是否还在）？

## 8. 实施顺序建议（R3 内部）

```
1. token 层重建（theme.css 重写 + 兼容映射）—— 不动组件先见效
2. 全局 base（focus-visible / reduced-motion / 触摸目标 / 语义地标）
3. 工作台信息架构（导航重组 + 管道式页面）
4. 任务卡监视墙（记忆点）
5. 空态与错误态补齐
6. 各工具页逐页迁移 token
```
